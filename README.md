## English

A lightweight, dependency-free toolkit that scans LLM-generated text for PII, credential, and policy-violation leaks before it reaches a user — and redacts what it finds.

> Companion project to [`LLM-Prompt-Injection-Test-Kit`](../LLM-Prompt-Injection-Test-Kit) — that one tests attack resilience on the **input** side, this one catches and redacts leaks on the **output** side.

### Overview

LLM applications can accidentally echo back PII, leaked credentials, or comply with injected instructions in their responses. This toolkit provides a set of heuristic detectors plus a `wrap()` helper so you can drop guardrail checks around any LLM call with a couple of lines of code.

### Installation

No dependencies beyond the Python 3 standard library.

```bash
git clone <this-repo>
cd LLM-Output-Guardrail
pip install -e .   # installs the `llm-output-guardrail` command
```

You can also just run the script directly without installing (`python llm_output_guardrail.py ...`).

### Usage

```bash
python llm_output_guardrail.py --text "Contact me at jane@example.com"
python llm_output_guardrail.py --file sample_outputs/pii_leak.txt --output report.md
cat some_output.txt | python llm_output_guardrail.py --output report.md
python llm_output_guardrail.py --file output.txt --policy custom_policy.json
python llm_output_guardrail.py --file output.txt --format json --output report.json

# after `pip install -e .`:
llm-output-guardrail --file sample_outputs/pii_leak.txt --format json
```

`custom_policy.json` is a plain JSON list of extra banned phrases:

```json
["do not reveal this", "internal use only"]
```

#### Wrapping your own LLM call

```python
from llm_output_guardrail import wrap

def call_my_llm(prompt: str) -> str:
    ...  # your Anthropic/OpenAI/etc. call here

safe_call = wrap(call_my_llm)
response = safe_call("Summarize this document")  # automatically redacted if unsafe
```

### CI Integration

`--fail-on-unsafe` exits `1` when `safe_to_return` is `False` — wire this in front of returning an LLM response to a user, or as a regression test that a given prompt no longer leaks:

```bash
llm-output-guardrail --file output.txt --fail-on-unsafe
```

```yaml
# GitHub Actions step
- name: Guardrail check on captured LLM output
  run: llm-output-guardrail --file output.txt --fail-on-unsafe
```

Without the flag, the exit code is always `0` — safe for ad-hoc scanning.

### Detectors

| Type | What it catches |
|---|---|
| `email` | Email addresses |
| `phone_number` | Phone-number-like digit sequences (7-12 digits) |
| `credit_card` | 13-19 digit sequences that pass the Luhn checksum |
| `aws_access_key` | AWS access key IDs (`AKIA...`) |
| `private_key` | PEM private key headers |
| `generic_api_key` | `api_key = "..."` style assignments |
| `banned_phrase` | Default + custom policy-violation phrases |

### Example Output

See [`sample_report.md`](./sample_report.md), generated by running the CLI against the three files in [`sample_outputs/`](./sample_outputs). The PII-leak sample produces:

```
| Type | Severity | Redacted Snippet |
|---|---|---|
| email | MEDIUM | `jan****om` |
| credit_card | HIGH | `411****11` |
| phone_number | MEDIUM | `+1 ****82` |
```

### Limitations

This is a heuristic, regex-based demo tool — good for catching obvious leaks and for learning/portfolio purposes, but not a substitute for a dedicated content-moderation service in production. For high-stakes applications, combine it with a real moderation API and human review.

## Türkçe

Kullanıcıya ulaşmadan önce LLM tarafından üretilen metni PII, kimlik bilgisi (credential) ve politika ihlali sızıntılarına karşı tarayan; bulduklarını redakte eden, hafif ve bağımlılıksız bir araç seti.

> [`LLM-Prompt-Injection-Test-Kit`](../LLM-Prompt-Injection-Test-Kit) projesinin tamamlayıcısıdır — o proje **girdi** tarafında saldırı dayanıklılığını test eder, bu proje ise **çıktı** tarafındaki sızıntıları yakalayıp redakte eder.

### Genel Bakış

LLM uygulamaları, yanıtlarında yanlışlıkla PII, sızmış kimlik bilgileri gösterebilir veya enjekte edilmiş talimatlara uyabilir. Bu araç seti, birkaç satır kodla herhangi bir LLM çağrısının etrafına guardrail kontrolleri eklemenizi sağlayan bir dizi sezgisel (heuristic) dedektör ile bir `wrap()` yardımcı fonksiyonu sunar.

### Kurulum

Python 3 standart kütüphanesi dışında bağımlılık yoktur.

```bash
git clone <this-repo>
cd LLM-Output-Guardrail
pip install -e .   # installs the `llm-output-guardrail` command
```

Kurulum yapmadan da doğrudan script'i çalıştırabilirsiniz (`python llm_output_guardrail.py ...`).

### Kullanım

```bash
python llm_output_guardrail.py --text "Contact me at jane@example.com"
python llm_output_guardrail.py --file sample_outputs/pii_leak.txt --output report.md

python llm_output_guardrail.py --file output.txt --format json --output report.json

# after `pip install -e .`:
llm-output-guardrail --file sample_outputs/pii_leak.txt --format json
```

`custom_policy.json`, ekstra yasaklı ifadelerden oluşan düz bir JSON listesidir:

```json
["do not reveal this", "internal use only"]
```

### CI Entegrasyonu

`--fail-on-unsafe`, `safe_to_return` değeri `False` olduğunda `1` ile çıkış yapar — bunu bir LLM yanıtını kullanıcıya döndürmeden önceki adıma, ya da belirli bir prompt'un artık sızıntı yapmadığını doğrulayan bir regresyon testi olarak bağlayın:

```bash
llm-output-guardrail --file output.txt --fail-on-unsafe
```

```yaml
# GitHub Actions step
- name: Guardrail check on captured LLM output
  run: llm-output-guardrail --file output.txt --fail-on-unsafe
```

Bu flag olmadan çıkış kodu her zaman `0`'dır — ad-hoc tarama için güvenlidir.

### Dedektörler

| Tip | Ne yakalar |
|---|---|
| `email` | E-posta adresleri |
| `phone_number` | Telefon numarasına benzer rakam dizileri (7-12 hane) |
| `credit_card` | Luhn kontrol toplamından geçen 13-19 haneli rakam dizileri |
| `aws_access_key` | AWS erişim anahtarı kimlikleri (`AKIA...`) |
| `private_key` | PEM özel anahtar başlıkları |
| `generic_api_key` | `api_key = "..."` tarzı atamalar |
| `banned_phrase` | Varsayılan + özel politika ihlali ifadeleri |
